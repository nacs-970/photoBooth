<decisions_made>

- **Walking skeleton / MVP mode**: 4 sequential plans, each a complete vertical slice. After Wave 1 a real user can see themselves and tap Start. After Wave 2 they complete one shot. After Wave 3 they finish a full session. After Wave 4 disconnect is handled.
- **CameraAdapter interface shape**: `attachPreview(el: HTMLVideoElement | HTMLImageElement)` — NOT `getStream()`. Rationale: Phase 2's TetheredAdapter uses MJPEG via `img.src`; no MediaStream exists. Screens must never call getUserMedia directly.
- **Repo structure**: two independent `package.json` files (`web/`, `server/`) + root `package.json` with only scripts + concurrently. No npm workspaces.
- **Vite proxy**: `web/vite.config.ts` → `server.proxy: { '/api': 'http://localhost:3001' }`. Fastify runs on 3001, Vite on 5173.
- **Shutter sound**: source from freesound.org (public domain), place at `web/public/sounds/shutter.mp3`. Plan 02 Task 1 includes this. PLACEHOLDER fallback if unavailable during execution.
- **Session state**: `export const session = $state({ screen, shots, ... })` in `session.svelte.ts` — object export, NOT primitive export (Svelte 5 cross-module reactivity requires object proxy).
