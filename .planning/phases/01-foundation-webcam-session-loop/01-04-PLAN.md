<objective>
Vertical slice: after this plan, unplugging the webcam (or revoking the camera permission) mid-session shows a `Camera disconnected` overlay modal with a `Retry` button instead of crashing. Tapping Retry re-runs the WebcamAdapter initialization; on success the modal dismisses and the underlying session resumes from where it was. Closes CAM-04, the final Phase 1 requirement.

Purpose: The disconnect-recovery flow is the user-visible safety net for the highest-risk environmental failure (USB cable). The pattern established here (overlay modal that preserves session state) is the template Phase 2 reuses for gphoto2 disconnect handling.

Output: DisconnectModal component, WebcamAdapter wired to call onDisconnect → session.showDisconnect, App.svelte mounting the modal above all screens, retry handler.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OS USB event → WebcamAdapter | Physical disconnect can fire MediaStreamTrack 'ended', devicechange, or (on revoke) NotAllowedError. All three paths must surface the modal without crashing. |
| Retry click → cameraAdapter.init() | Re-running getUserMedia may prompt for permission again (browser-dependent). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-DoS | Denial of Service | Disconnect during capture leaks the in-flight Blob promise; repeated Retry could leak streams | mitigate | handleRetry in App.svelte always calls cameraAdapter.dispose() before init() — dispose stops all tracks and removes listeners (Plan 01 contract). Failed Retry keeps the modal visible and does not call hideDisconnect — no orphan state. |
| T-04-IL | Information Disclosure | Modal Retry showing camera content from a previous user (kiosk multi-guest scenario) | accept | Phase 1 is single-session-at-a-time; resetSession returns to idle and revokes objectUrls. The modal only re-attaches the live preview, not historical shots. |
| T-04-Crash | Tampering / DoS | Unhandled NotAllowedError on initial init crashes the SPA | mitigate | IdleScreen wraps init in try/catch; any thrown error calls showDisconnect() so the modal serves as a generic error fallback. Permission-denied surfacing to a dedicated screen is acknowledged as deferred polish — Phase 1 surface is the modal as the bounded-error path. |
| T-04-SC | Tampering (Supply Chain) | No new packages installed | accept | All dependencies vetted in Plan 01. |
</threat_model>
